# 07 · 实施路线与验收标准

状态：后续执行计划。**本轮只交付设计，以下阶段尚未执行。**

## 1. 交付顺序与依赖

```text
M0 契约、基线与存档基础
  → M1 时间、天气与潮汐
  → M2 群体生态与规则控制
  → M3 两栖物种与海上来客
  → M4 初岛胜利和三条考验路线
  → M5 定时真实 Agent 接入
  → M6 联合试玩、性能与可交付版本
```

模型接入前先让确定性规则走通全部玩法，便于识别后来出现的问题属于地图、机制还是模型提案。M5 完成之前不能称为“已经加入真实 Agent”。

## 2. M0：可追溯的实现基础

**产物**

- 冻结一份现有 V2 合法存档样本和关键玩法录像/截图；不包含用户私人存档。
- 确认当前源码、活动修改和部署文件归属，建立本次实现的明确工作范围。
- 定义 `clock.tick`、event seq、命令 ID、职责槽位、运行世代和所有权的契约。
- 实现 V3 数据校验、IndexedDB 原子检查点、单写入者、导出/导入及迁移备份基础。
- 明确 V2 兼容继续入口的交付方式：同包兼容启动或有版本标识的旧入口，实际验证可用。
- 对现有目标设备记录帧率、模拟耗时、实体数量、存档大小基线。
- 选定并验证提案服务 SQLite 驱动、目标 Node 版本与构建打包方式；此时不配置真实密钥。

**完成条件**：V2 原样继续运行；V3 空壳可保存往返；坏导入不覆盖好存档；两个标签页不能同时写入；所有新增字段有明确权威来源。

## 3. M1：统一时钟、天气和潮汐

**工作**

1. 提取时钟，保持 360 秒一日和现有暂停、1/2 倍速语义。
2. 加入日段事件、独立天气随机流、五种天气、日历预报和保护期。
3. 集中计算天气效果，保证小雨原有野生食物 1.6 倍规则不被重复计算。
4. 将潮位、风雨增水接入规则、Shader 与浮力；实现导航水位桶和路径失效处理。
5. 增加预报 UI、天气过渡、雨雾与夜间可见度；提供低画质参数。

**完成条件**：固定种子天气可回放；已预报的风雨不突然改期；时间不会在暂停/后台推进；三种潮位下关键位置可达；水面与身体没有明显浮离。

## 4. M2：岛内群体生态

**工作**

- 从真实物种实体建立有限群体，保留个体 ID 与原有行为执行层。
- 加入观察、遭遇、群体结构版本、机会和纯规则控制器。
- 实现觅食换区、风雨避险、晨昏活动、有限追猎和资源竞争。
- 将统治、放归、同伴命令放在野生群体意图之上。
- 增加开发观察视图：选中某个群体可看到当前意图、来源、目标和实际行为；普通界面仍是生物信息。

**完成条件**：至少能在实景看到三种不同原因导致的群体活动变化；食物节点真实扣减；没有全图追踪玩家；规则模式无需网络即可持续运行。

## 5. M3：海上来客

**工作**

- 新建潮背螈、砾牙滩蜥的原创可编辑模型及海陆动画，接入资产清单和图鉴。
- 实现预检海路、登陆/返海过渡，修复现有岛缘限制与新移动类型的冲突。
- 实现来客机会、配额预留、预警、真实出场、岸上活动、离岛和结局。
- 新增背包投喂、携带/归还口粮及自动入库排除、群体撤退、海上成员一次性掉落与追随上限。
- 将海上来源死亡从常住野生 150 秒恢复分支中分离。

**完成条件**：两种物种均能从远海可见地抵达并实际离开；高低潮可达；重复消息和重载不重复出生；发生错误会明确中断且可恢复；单次事件不会超过压力上限。

## 6. M4：初岛胜利

**工作**

1. 将基础旅程与章节目标分开，修正原先“第一章完成”文案。
2. 实现 W1–W6、安居连续计时与即时中断事件。
3. 实现玩家主动预约、确定性风雨/来客安排、三条路线证据与退款边界。
4. 实现 ChapterWon 幂等提交、结算 UI、继续本岛与存档错误反馈。
5. 完成正式 V2 → V3 转换：既往进度保留、新考验从未完成开始、600 秒适应保护。

**完成条件**：三条路线分别能在真实规则中完成；所有必要资源可由正常玩法获取；模型服务关闭时也能通关；胜利保存重载后保持，继续游戏不撤销或重复奖励。

## 7. M5：定时真实 Agent

**工作**

- 实现两个职责的真实提示词组装，按局部观察与合法动作目录生成请求。
- 接入同源提案服务、SQLite job、身份隔离、配额、超时与熔断。
- 实现 120/180 秒调度、共同槽合批、ready inbox、40 秒模拟接受窗口和下一 tick 应用。
- 完成源输入哈希、群体版本、当前前置、command ID 与终结槽去重。
- 用 Mock 先验证失败、晚到、重复和恶意输入，再配置真实供应商。
- 真实调用记载实际模型、请求次数、延迟、用量和应用结果；不将“HTTP 200”直接当作世界控制成功。

**完成条件**：看到并证明“真实模型返回 → 通过校验 → 某个群体实际改变行为”的完整链；同局断网仍可继续；满预算时降级，不阻塞或集中补发；没有密钥进入客户端资产或存档。

## 8. M6：联合验收与可交付版本

**工作**

- 完成不少于一个 45–60 分钟有效 1 倍速的真实模型完整局，包含时间天气、两种海上物种、一次有效潮汐考验和胜利。
- 用规则/Mock 完成其它两条路线和故障场景；不为了每个异常测试重复付费调用。
- 在桌面和 390px 手机视口检查目标面板、来客提示、投喂、预报和结算的实际操作。
- 做最大实体/风雨场景的模拟耗时、渲染、内存与保存检查。
- 保存证据包、已知问题、构建版本和真实调用次数；说明哪些是自动化模拟，哪些是真实浏览器和模型。
- 更新根 README 和验证说明；生成可运行构建。发布是独立的后续动作，不能在完成构建后自动宣称线上已更新。

**完成条件**：下述发布阻断项清零，验收证据与当前代码版本一致，所有未完成体验明确列入已知问题。

## 9. 核心验收矩阵

| 编号 | 场景 | 必须成立 |
| --- | --- | --- |
| T01 | t=0、240、360、1800 | 分别为第 1 日 08:00、第 2 日 00:00、第 2 日 08:00、第 6 日 08:00；完整日数另算 |
| T02 | 1/2 倍速、暂停、切后台再回来 | 使用相同玩家输入与已记录意图时，同模拟 tick 规则结果相同；离线不补算天气、攻击或 Agent 槽 |
| T03 | 相同天气种子与回放输入 | 天气顺序、潮位、预报与效果一致 |
| T04 | 风雨出现与考验预约 | 至少 60 秒预警；不覆盖已公开日历，不与普通敌对压力叠加 |
| T05 | 低/中/高潮 + 风雨最大增水 | 巢区及必要建造槽安全，四个栖息地可发现，来客有撤离路线 |
| T06 | 涨潮使路径失效 | 实体重规划或明确脱困；不无限卡住，不凭空穿陆地 |
| T07 | 投喂、受伤、食物耗尽、日段变化 | 实际事件改变群体观察和意图，reason 文本不能伪造事件 |
| T08 | 群体被玩家统治/放归 | 旧模型结果被拒绝；玩家控制不被群体任务覆盖 |
| T09 | 两群争用最后一份食物 | 按稳定顺序扣减，不为负、不重复增益 |
| T10 | 每种海上物种完整行程 | 预警→海上实体→登陆→互动→离岛均可观察，成员 ID 连续 |
| T11 | 重复/乱序发送同一登陆提案 | 一支队伍、一份配额、一次掉落和一次结算 |
| T12 | 来客被击败后推进 150 秒再重载 | 不复活为新海上队伍，不重复奖励 |
| T13 | 新手保护或配额已满 | 不产生非法敌对登陆；可见等待/降级原因 |
| T14 | 真实模型超时/坏 JSON/返回额外数值 | 无非法写入、无额外修复调用、世界继续 |
| T15 | 提案合法但应用前目标消失、天气改变 | 按单条前置拒绝或合法适配，不覆盖新状态 |
| T16 | 结果在 40 秒模拟窗口后或新 runEpoch 返回 | 不应用、不复活已终结槽 |
| T17 | 2 倍速持续 1 小时、反复刷新/新建存档 | 服务端限流仍成立；不补发漏掉的请求；真实次数不超预算 |
| T18 | 共存路线 | 真实扣 16 背包食物、有和平窗口、成员实际离开后才记完成 |
| T19 | 驱离路线 | 有玩家侧伤害证据、按阈值撤退，不能把自然离开当作玩家驱离 |
| T20 | 守巢路线 | 加固只扣一次，40 起始/20 下限、2 守卫和持续时间逐项核验 |
| T21 | active 中重载、失败后重试 | 无重新出生/重复收费；阶段及证据一致；失败可再次预约 |
| T22 | 已完成六项引导但尚无新考验 | 不显示正式通关、不写 ChapterWon |
| T23 | 安居中一 tick 低粮或发生恢复事件 | 立即重置计时，不被 UI 每秒采样漏过 |
| T24 | 全条件满足但时间不足 1800 秒 | 不提前胜利；达到时机只结算一次 |
| T25 | 胜利后缺粮、导出、重载、继续 | 胜利仍在，不重复发事件，不撤销章节 |
| T26 | V2 迁移、拒绝升级、坏 V3、磁盘存储失败 | 原存档保留且可继续；错误有恢复/导出入口 |
| T27 | 两标签页写入、隐藏后接管、旧页醒来 | 旧 fencing token 无法覆盖新检查点，旧请求不能生效 |
| T28 | 来客退出、模型列表与粒子反复创建销毁 | 实体、监听器、材质、几何体和日志规模有上限 |

## 10. 自动化范围

拟新增有意义的规则测试文件：`clock-weather.test.js`、`ecology.test.js`、`ecology-contract.test.js`、`migration.test.js`、`chapter.test.js`、`persistence-v3.test.js`。服务端测试覆盖 job 去重、额度、claim/deadline、身份隔离与失败分支。

不为每一个常量写“等于文档中的数字”式测试。优先验证守恒、不重复应用、因果顺序、可达性、连续窗口和可恢复性。调参数之后只改被设计改变的行为预期，不通过修改测试掩盖状态越权。

回归继续运行现有 `npm test`、`npm run build` 和已支持的浏览器实际交互测试。后续如新增服务测试命令，应在 package 脚本中明确，不在本设计中声称当前已有某个命令。

长程规则测试采用至少 5 个固定种子（含 73429）各运行 7 游戏日，检查配额、资源上下界、无非法实体和调度去重。确定性回放测试使用已接受模型命令及其应用 tick，不重新询问模型来证明一致性。

## 11. 平衡与性能目标

| 维度 | 首轮目标 | 怎么判断 |
| --- | --- | --- |
| 通关时长 | 初次熟悉后约 30–45 分钟有效 1 倍速 | 记录实际步骤和模拟时间；超时不自动判玩家失败 |
| 路线可行 | 共存、驱离、守巢均可达成，互不要求另一条能力 | 三份独立正常资源流程；不能靠修改存档直接充资源作平衡证据 |
| 模型价值 | 对资源枯竭、投喂、受袭、风雨至少产生可解释的不同合法意图 | 同观察对照规则/模型选择，再观察真实执行；不把更高攻击频率当成更聪明 |
| 付费调用 | 正常 1 倍速理论约 40 次/小时，上限 48 | 以服务端供应商尝试数核对，包含失败尝试 |
| 模拟耗时 | 目标桌面固定 tick p95 不超过 4 ms | 在 M0 同设备基线下比较；未达标先查感知、A* 和日志分配 |
| 浏览器性能 | 桌面争取 60 FPS，手机档争取稳定 30 FPS | 风雨 + 64 非玩家实体压力场景；分别报告模拟与渲染瓶颈 |
| 存档 | 正常单局导出目标小于 1 MiB，导入上限 2 MiB | 长程运行后检查；回放与模型原文不挤占普通存档 |
| 模型故障体验 | 无输入冻结，无隐藏补袭击，仍能完成考验 | 网络断开、超时、格式坏和服务重启场景 |

这些是验收目标，不是已经取得的性能数据。目标设备未明确时先记录设备配置，不能用开发机结果承诺所有手机性能。

## 12. 证据包

实施后在忽略的 `artifacts/roadmap-v3/<timestamp>/` 保存：

- `report.md`：当前 SHA、规则版本、测试命令、结果、未通过项。
- `scenario-events.jsonl`：玩家行为与实际生态/天气/考验事件；关键断言对应事件 ID。
- `agent-usage.json`：实际调用数、模型、延迟、返回合法率、应用率、降级原因；密钥清除。
- 三条路线的通关存档及简短步骤记录。
- 桌面/手机截图，以及海上出现、登陆、返海和天气变化的短视频或连续帧。
- 模拟/渲染性能采样与 V2/V3 迁移恢复证据。

人工试玩、Mock、规则自动化和真实模型分别列出，不互相代替。若服务失败只完成规则局，要准确报告“规则版通关已验证，真实 Agent 尚未验收”。

## 13. 发布阻断与延后事项

以下任一情况阻断“本次玩法完成”：模型直写数值或胜利；密钥泄露到浏览器；海上生物瞬移入巢；初岛没有合法通关路线；暂停后时间仍推进；旧结果覆盖新世界；重复出生/扣费/奖励；迁移覆盖旧档；模型掉线使游戏无法继续；文档与实际规则存在导致玩家误解的差异。

可延后事项：更多海上物种、季节、永久生态灭绝、自由建筑摆放、全海域探索、后续岛屿、联网排行榜、账号云存档、长期跨局模型记忆。它们不应成为首岛版本的隐性前置。

## 14. 调参和决策记录规则

首轮基线集中在 [README](README.md)。改变日长、调用周期、物种伤害、预算、风雨产量、通关人口/存粮或考验长度时，同时更新专题、样例和验收预期，并给出试玩依据。

不通过增加固定坏事配额让 Agent 显得活跃，也不在通关设计中增加只能靠模型临场认可的隐形条件。未验证的效果继续标为假设，直到出现可复查的事件与试玩证据。
