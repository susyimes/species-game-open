## 1. 目标体验

玩家带领小芽从安家开始，认识会随昼夜、食物和天气改变活动的岛上物种；看到海面上的两栖来客逐渐靠岸，决定接纳、引导或抵御；在一次风雨涨潮后建立能够持续生活的家园，获得明确的初岛胜利。通关后可以留在本岛继续探索。

Agent 负责为野生群体选择下一段活动意图，例如换一片觅食地、避开最近遭到捕猎的海岸、追随潮水登陆。个体实际行走、采集、受伤、恢复、资源变化和胜利判断全部经过确定性规则。玩家应从生物的行动看出变化，普通游戏界面不展示模型、请求、Token 或 Agent 调度信息。

## 3. 首版设计决策

| 事项 | 首版选择 | 原因 |
| --- | --- | --- |
| 游戏节奏 | 实时探索；1 个游戏日仍为 360 秒模拟时间 | 保留已有移动、生产和恢复节奏 |
| Agent 组织 | `IslandEcologyAgent` 与 `MarineMigrationAgent` 两个逻辑职责，共用一个有预算限制的服务 | 分开岛内与海上知识；不为每只生物建立模型会话 |
| 群体规模 | 岛内最多 8 个决策群体；海上最多 2 支活跃来客队伍 | 足够表现地域差异，也便于验收和控制成本 |
| 调度 | 岛内每 120 秒、海上每 180 秒模拟时间；同刻到期合并为一次调用 | 决策能影响一段活动，而非逐帧操作 |
| 实时执行 | 20 Hz 原有模拟 + 1 Hz 生态检查 | 模型延迟不阻塞玩家输入、移动和战斗 |
| 离线与暂停 | 冻结世界和游戏调度；不补算离线攻击、天气或出生 | 延续现有本地休闲游戏语义 |
| 天气 | 晴、多云、小雨、薄雾、风雨；额外模拟短周期潮汐 | 同时影响可见性、资源、觅食与来客 |
| 两栖新物种 | 潮背螈、砾牙滩蜥 | 分别提供和平迁徙与机会性争食行为 |
| 胜利 | 完成引导、建设家园、适应环境、解决潮汐考验并稳定生活 | 产生可理解、可验证的初岛终点 |
| 通关后的状态 | 胜利永久记录；可继续本岛 | 不凭空声称已实现第二座岛或下一阶段 |
| 默认模型配置 | 可配置的服务端适配器；先规则、后 Mock、再真实模型 | 不在设计阶段锁死供应商、型号或费用承诺 |
| 数值权威 | 本项目浏览器中的纯规则引擎是单机存档权威；服务端只提供提案 | 适配现有静态 Web 架构；不直接复制 Edict 的整套后端游戏 |

## 5. 玩家的一段示例旅程

1. 清晨采集时，苔背团兽在原野觅食。小芽多次捕猎后，该群体下一次决策倾向迁往较安静的林缘；撤离过程能被看见。
2. 第一次小雨提高野生浆果再生。长喙泽鸟向浅滩移动，灯囊浮虫在傍晚更活跃。界面给出下一段天气和潮水方向。
3. 远海出现潮背螈背脊与水纹。玩家看到海岸提示后提前前往，靠近观察或消耗背包食物投喂；它们吃饱后离去，记录这次遭遇。
4. 族群壮大、掌握环境适应后，玩家在巢边主动开始“潮汐来客”考验。引擎安排一段已预告的风雨涨潮与一支来客队伍。
5. 玩家用食物引导来客、守卫驱离，或加固巢区守过风雨。满足其余建设和安居条件时触发“初岛安居”，展示本局真实经历并允许继续探索。

以上是可实现的因果示例，不是必须照顺序发生的固定剧本。普通生态行为可随局势变化；通关考验由规则保证有可执行入口。

## 6. 实施边界

首版包含两个新物种、低频 Agent、海上航路、投喂所需的携带口粮操作、完整天气与潮汐、初岛通关、必要存档迁移、开发诊断及自动化验收。不扩展到多人联机、账号云存档、全球气候、完整生态食物网、永久物种灭绝、自由造岛或后续文明阶段。

只接通真实模型服务，或只在 UI 上显示新的天气文字，都不能视为完成。完整交付需要动物实际执行意图、海上来客真实移动、天气影响规则、胜利可由引擎复现，且模型不可用时仍能完成一局。

实施顺序为 **M0 契约与记录 → M1 时间天气 → M2 群体生态 → M3 海上来客 → M4 初岛胜利 → M5 真实 Agent → M6 联合验收**。M4 先用规则控制器完成通关，M5 再验证模型带来的行为差异。
