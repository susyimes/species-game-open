# 05 · 初始小岛的胜利条件

状态：拟实施规格。章节 ID `first_island`，胜利名称 **初岛安居**。

## 1. 胜利目标

玩家需要建立有补给的家园，获得足够的环境适应能力，认识岛屿，并亲自处理一次海上来客考验。目标面板从新局就能查看，不等玩家做完引导才突然追加未知门槛。

原有六项旅程仍是教学链。完成后显示“基础旅程已完成”，切换到初岛目标进度；不再用“第一章已完成”提前宣告通关。

## 2. 正式胜利公式

以下条件全部满足时，由纯规则引擎提交一次 `ChapterWon`：

| ID | 条件 | 精确定义 |
| --- | --- | --- |
| W1 | 完成基础旅程 | 六个既有任务 ID 全部存在于 `completed`，不能仅相信 `quest=6` |
| W2 | 族群站稳脚跟 | `population(state) >= 10`；包含小芽，不包含被统治的野生动物 |
| W3 | 建成家园 | 至少 1 育幼巢、2 浆果圃、1 储藏堆，均 `progress === 1` |
| W4 | 适应全岛 | 4 个有效栖息地已发现；当前安装至少 3 种不同基础适应及 1 项具有合法前置的专精 |
| W5 | 处理潮汐来客 | 一个有效 `first_island_tide_trial` 已按共存、驱离、守巢中至少一条规则完成 |
| W6 | 安居经过检验 | 有效模拟时间至少 1800 秒；最终安居条件连续保持 180 秒 |

最终安居条件为：W1–W5 仍成立，族群食物始终至少 30、巢区 12 单位内没有当前主动威胁、玩家没有在窗口内被击倒、同伴没有在窗口内因战斗进入回巢恢复。

W6 的 180 秒可以在累计时间达到 1800 秒之前开始累计；胜利仍不得早于 t=1800。暂停和离线不增长累计。既有目标完成后若条件不满足，界面明确指出原因，而不是只给一个不透明分数。

### 2.1 判定伪代码

```js
// 设计伪代码；不是当前实现。
onEveryFixedTick(state) {
  if (state.chapter.status === 'won') return;
  const ready = allOfW1ToW5(state);
  const stable = ready && foodAtLeast30(state)
    && noActiveThreatWithinNestRadius12(state)
    && noNewPlayerKnockdownOrCompanionCombatRecovery(state);

  if (!stable) state.chapter.stableSinceTick = null;
  else state.chapter.stableSinceTick ??= state.clock.tick;

  if (state.clock.tick >= 1800 * 20
      && state.chapter.stableSinceTick !== null
      && state.clock.tick - state.chapter.stableSinceTick >= 180 * 20) {
    commitChapterWonOnce(state);
  }
}
```

界面可每秒刷新，但食物跌破阈值、玩家倒下或同伴恢复等事件要在发生 tick 立即打断安居累计，不能被 1 Hz 采样漏过。饥饿、建设和孵育消耗食物同样会重置累计；不会撤销已经完成的探索、旅程或考验。

## 3. 目标的可达到性

1 育幼巢正好把现有容量从 6 提升为 10；从开局增加 4 个同伴共需 72 食物。四座所需设施共花 32 食物、54 材料，现有槽位数量足够但仍要验证高水位可达性。

两座浆果圃在晴天产食 10/分钟；10 人耗食 10.8/分钟，只需很少额外采集即可维持。风雨产量降到 6/分钟，120 秒净消耗约 9.6，给最后的 30 食物缓冲和“储藏堆”提供用途。

三个不同基础适应加一项专精可由多种组合达成。示例“轻盈长足 + 苔纹背甲 + 蓄能长尾 + 琥珀脂尾”共需 `18+24+22+26=90` 进化点。初始 12 点与六项引导奖励共 78 点合计也是 90；探索和孢子还提供额外进化来源。因此通关不必反复刷捕猎，也不要求必须取得统治能力。

四个栖息地必须有可步行到达的发现边缘；若地图实测发现某区域只能深水到达，要修正发现点或明确把侧鳍作为前置后重新核算，不能让文档声称路线自由而实际锁死进化选择。

首局目标体验为约 30–45 分钟有效 1 倍速游玩；慢玩家无硬期限，2 倍速相应缩短。这是体验目标，不是已测出的平均通关时间。

## 4. 潮汐来客考验入口

当六项引导完成且 `simSeconds >= 900` 时，巢边解锁“迎接下一次潮汐”。目标面板说明三种可行准备，玩家主动预约，不按某天强制开战。

基础检查：玩家在巢边 5 单位内、无正在进行的考验、没有敌对队伍占用预订名额、地图已经通过考验航路预检。人数 10、全部建筑和进化可以在考验后补齐；考验入口不额外要求已满足全部胜利条件。

引擎安排一支 2 只砾牙滩蜥的队伍、一个 120 秒风雨窗口和已验证海岸，使用同一来客预算。Agent 可以在合法变体中选择岸边觅食方向与接近方式，不能决定考验是否成功，也不能拒绝所有选项从而永远没有通关事件。

普通规则控制器必须能够完整运行考验。正常情况下，预约在两游戏日内取得合法窗口；额度或地形阻碍要显示原因并给出取消/重试入口。

## 5. 考验阶段

| 阶段 | 持续或触发 | 玩家看到什么 |
| --- | --- | --- |
| `ready` | 满足入口 | “可以迎接下一次潮汐”与准备提示 |
| `scheduled` | 等待已公布天气之后的合法涨潮窗口 | 岸段、预计开始时刻、所需准备 |
| `announced` | 开始前至少 60 秒 | 海上水纹和预警；可取食物、召唤守卫或加固 |
| `active` | 固定 120 秒风雨窗口 | 来客真实登陆、路线目标和剩余时间 |
| `departing` | 窗口结束，或已形成有效驱离/共存结局 | 来客实际返海；逐个记录成员结局 |
| `resolved` | 所有队伍成员离岛、被击败或被玩家接管 | 显示所达成的处理方式 |
| `cooldown` | 失败或可恢复中断后 | 原因、准备提示、重新预约 |

考验队伍可在预警阶段已经出现在远海，但上岸不早于 active 开始。登陆通道需要保证 active 开始后 15 秒内可完成过渡；做不到应延期整场，不能瞬移补足。

达到某条路线的行动条件只标记 `routeEligible`。最终通关证据必须等队伍实体结局全部确定，不能刚投喂或刚砍一刀就算完成。

## 6. 三条合法完成路线

### 6.1 共存：以食物引导来客

- 在本场同一队伍完成两次有效投喂，每次从背包扣 8 食物，共 16；间隔至少 15 秒。可使用巢边“携带口粮”分两次准备，基础 12 格背包不要求同时携带 16。
- 从第一次有效投喂到形成共存结局，玩家及其同伴、追随者不得再伤害该队伍；可在第一次投喂前从冲突转向安抚。
- 两次投喂后至少维持 30 秒和平，且队伍沿引导路线返回海岸，最终所有成员实际离岛或被合法接管。
- 规则在这些条件成立后发起平静撤离；不要求模型恰好选择“合作”。

说明：首次投喂会中止该队伍主动敌对 90 秒，足以完成第二次和和平窗口。守卫的自动伤害也会影响和平判定，准备提示应解释可以临时改为采集或拉开距离。

### 6.2 驱离：守卫与小芽共同抵御

- 玩家侧造成有效战斗事件，触发“任一成员 HP ≤35%”或“队伍至少 1 只被击败”的群体撤退条件。
- 队伍由此进入撤退，所有剩余成员实际返海；被击败或被合法统治的成员记作终结。
- 如果伤害完全来自其它野生动物、没有玩家侧参与，则不计这条路线；可以继续采用共存或守巢。

不要求杀光两只，更不要求灭绝一个物种。撤退后的敌人停止主动追击，玩家可停止捕猎节省资源。

### 6.3 守巢：准备物资，守过风雨

- 预警期间在巢边完成一次“加固巢区”，从**族群仓库**扣 12 材料；同一场只扣一次，效果覆盖该场 active 窗口。
- active 开始时仓库至少有 40 食物；整个 120 秒窗口中食物不低于 20。
- 窗口内至少连续 60 秒，小芽与至少 2 位分工为守卫且不在受伤恢复中的同伴位于巢心 8 单位内。
- 本窗口玩家未被击倒，同伴因战斗进入回巢恢复的事件不超过 2 次。
- 窗口结束后规则让来客饱和撤离，最终队伍离岛或其它合法终结；不能删除实体替代返海。

“加固”首版是有期限的巢区防护状态，抵消圈内风雨体力恢复惩罚，不另造一套建筑 HP。守巢用资源准备和岗位组织完成考验，是明确允许的低战斗路线。

### 6.4 多条路线同时成立

分别保存每条路线的真实证据；`completedRoutes` 可有多个。展示主路线时按最早满足的行动条件时间选择，时间相同按共存、驱离、守巢顺序；不影响奖励、胜利门槛或玩家之后的自由行动。

## 7. 失败、中断与防软锁

| 情况 | 结果与恢复 |
| --- | --- |
| 玩家倒下 | 使用已有回巢和背包损失；本次共存/驱离仍可按真实结果成立，守巢路线失效；若全部路线失败则重试 |
| 物资不足 | 不扣除不完整费用；提示需要背包食物或仓库材料，允许改走其它路线 |
| 120 秒结束但没有路线证据 | 来客沿路撤离，考验失败；等待 180 秒后可重新预约 |
| 导航/地图错误 | 考验 `interrupted`，不计失败/成功；已明确消耗的正常食物仍为实际投喂，未兑现加固预订费按规则返还一次 |
| 请求超时、坏 JSON、断网 | 规则控制器照常完成合法登陆与行为，不因此让考验失败 |
| 暂停、后台 | 所有阶段冻结，回来继续 |
| 重载 active 存档 | 保留队伍、阶段、剩余 tick、行动证据、费用事件，禁止再次收费或出生 |
| 只反复击败刷新小怪 | 不能替代本场考验证据，常住动物不计为考验来客 |
| 第三方野生动物干预 | 可有真实影响，但不伪造玩家贡献；守巢条件仍可验证 |

明确被系统取消且尚未进入 active 的加固费用，可以用绑定原费用事件的一次性退款恢复。已进入 active 的加固视为已经使用，不因玩家失败退费；退款标记必须存档。

首岛没有永久失败，也没有超时灭绝；已经建成的家园与探索进度不会因考验失败清空。玩家可以继续收集和进化后再来。

## 8. 胜利结算

所有判定在 tick 中完成一次：

1. 写入稳定 `chapterWinId`、规则版本、胜利 tick、达成条件快照和考验事件引用。
2. `chapter.status = won` 为不可逆里程碑；继续游玩后食物减少或人口条件变化不撤销胜利。
3. 显示“初岛安居”：经历的日数、族群规模、已安装进化、家园设施和实际考验处理方式。
4. 提供“继续在岛上生活”“导出旅程”“返回标题”。未开发下一座岛时不提供可点击但无法使用的“前往下一岛”。
5. 弹窗暂停模拟；继续后恢复普通生态，第一章考验不再自动生成。

首版奖励是永久章节记录、见闻页的家园纪念和可重新查看的结算，不发放可反复领取的资源。是否增加装饰奖励可后续另定，不作为实现胜利所必需的资产依赖。

如果触发胜利时保存失败，当前内存中的 `won` 保持，但显示明确存档失败提示并提供导出；不能谎称已经安全保存到设备。重试保存不得重复创建胜利事件。
