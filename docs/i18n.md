# Language presentation boundaries

The current `src/` game localizes through `src/i18n.js`, `src/locales/en.js`, and explicit `msg()`/`tr()` calls in UI templates and renderers. Chinese source messages serve as stable dictionary keys and the Simplified Chinese dictionary. `msg()` interpolates named values; `tr()` presents core configuration names, reasons, and stored journal/notification text without altering the source data. `src/locales/patterns.js` records complete dynamic message patterns, including placeholder order, for old saves. A phrase fallback covers historical concatenated messages at these text presentation boundaries.

The language selector uses native `select` elements and is available in the welcome dialog, top bar, and Help. Existing gameplay key handling already skips `input`, `textarea`, and `select`, preserving native keyboard operation. Switching updates `document.lang`, page title/description, explicit static labels and accessible attributes, HUD, coaching, open dialogs, target options, audio controls, and world labels. Open dialog details/scroll and evolution choice are retained. The world, player, inventory, IDs, saves, simulation, and ecology API inputs retain their existing values.

Chinese literals remaining under active `src/` are dictionary keys, the bilingual language-control labels, untranslated source configuration/message data, and internal comments/error/schema inputs. They are translated when rendered. `legacy/` is the original archived compatibility runtime and remains unchanged, as do the historical `gameplay-overview.html`, art, licenses, and documents.

Run `npm test` and `npm run build`. For a static local preview, run `npm run preview` and open `http://127.0.0.1:4186/`. For the normal development workflow, run `npm run dev` and open `http://127.0.0.1:5196/`. This preserves the existing backend/offline configuration. No translation dependency or translation network request is used at runtime.
